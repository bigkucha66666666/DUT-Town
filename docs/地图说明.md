# 地图说明

本文件说明地图数据的结构与编辑方法。**地图 JSON 是唯一数据源**：Web 查看器、PNG 平面图、栅格化引擎都从它派生，不反向写入。

---

## 1. 文件

| 文件 | 作用 |
| --- | --- |
| `world/maps/sem_1f.json` | 场景一：经济管理学院楼一层 + 南门小广场（当前主场景） |
| `world/maps/dut_sem.json` | 场景二：学院楼及周边（场地级） |
| `world/map_loader.py` | 载入 / 校验 / 栅格化 |
| `tools/render_map.py` | PNG 平面图 |
| `web/js/app.js` | 浏览器端像素风渲染（走位判定与 `map_loader.py` 保持一致） |

---

## 2. 坐标约定

- 单位：**米**。`meta.world` 给出地图尺寸，`meta.tile_size` 给出栅格大小（都是 1m）。
- 原点在**左上角 = 西北角**；`x` 向东增大，`y` 向南增大。
- 所有几何都是**矩形** `{ "x": 左上角x, "y": 左上角y, "w": 宽, "h": 高 }`。
- 为什么只用矩形？矩形 + 语义字段足够表达这个尺度的建筑，而且重叠、包含、连通这些校验可以做得又快又可靠。需要异形时再引入 `polygon` 类型。

## 3. 数据结构

```jsonc
{
  "meta":   { "id", "name", "version", "scene", "units", "tile_size",
              "world": {"width","height"}, "default_floor", "disclaimer", "sources", "notes" },
  "floors": [ { "id": "1F", "name": "一层", "status": "modeled" | "pending" } ],
  "ground": [ { "id", "name", "category", "rect", "level"?, "capacity"?, "note"? } ],
  "buildings": [ { "id", "name", "category", "focus"?, "rect", "floors"?, "modeled_floors"?,
                   "area_m2"?, "height_m"?, "open_hours"?, "allowed_roles"?, "entrances"?, "note"? } ],
  "rooms":  [ { "id", "name", "floor", "category", "rect", "parent",
                "capacity"?, "open_hours"?, "allowed_roles"?, "note"? } ],
  "furniture": [ { "id", "type", "name", "room", "rect" | "grid", "solid"? } ],
  "spawns": [ { "id", "name", "pos": [x, y], "kind": "entrance"|"landmark"|"transport"|"gateway" } ]
}
```

### ground 的 `category`

`road` 道路 · `plaza` 广场 · `green` 草地 · `parking` 停车场 · `shelter` 车棚 · `path` 步道

### rooms 的 `category`

`corridor` 走廊 · `lobby` 大厅 · `hall` 多功能厅 · `office` 教师办公室 · `classroom` 教室 · `lab` 实验室 · `service` 服务用房 · `vertical` 垂直交通

### furniture 的 `type`

`desk` 课桌 · `office_desk` 办公桌 · `chair` 座椅 · `bookshelf` 书架 · `plant` 绿植 · `sofa` 沙发 · `table_round` 圆桌 · `meeting_table` 会议桌 · `counter` 吧台 · `reception` 前台 · `blackboard` 黑板/幕布 · `whiteboard` 白板 · `podium` 讲台 · `elevator` 电梯 · `stairs` 楼梯 · `coffee_machine` 咖啡机 · `water_cooler` 饮水机 · `sink` 洗手台 · `bulletin` 公告栏 · `mat` 地垫

Web 端每种 `type` 对应一个程序化像素画绘制函数（`web/js/app.js` 的 `DRAW`）；加了新 type 记得同步加一个画法，否则会退化成默认的桌子。

### 家具的两种写法

单件：

```json
{ "id": "fu_whiteboard", "type": "whiteboard", "name": "白板",
  "room": "rm_seminar", "rect": { "x": 41, "y": 6, "w": 8, "h": 1 } }
```

阵列（课桌、座椅这类重复摆放，写一条就够）：

```json
{ "id": "fu_class_desk", "type": "desk", "name": "课桌", "room": "rm_classroom",
  "grid": { "x": 9, "y": 13, "cols": 5, "rows": 4, "dx": 4, "dy": 4, "w": 1, "h": 1 } }
```

`grid` 会被 `expand_furniture()` 展开成 `fu_class_desk_r1c1` 这样的独立家具（Python 和 JS 两侧实现一致）。

### 语义字段（为后面的智能体准备）

| 字段 | 含义 | 用在哪 |
| --- | --- | --- |
| `open_hours` | 开放时间，如 `"07:00-22:30"` | 智能体按时间决定能不能进 |
| `allowed_roles` | 可进入角色 `["student","teacher","staff"]` | **引擎硬校验**，不交给 LLM 判断 |
| `capacity` | 容量（人） | 拥挤度、排队模拟 |
| `parent` | 房间所属建筑 id | 归属关系 |
| `floor` | 楼层 | 楼层切换、垂直交通 |
| `room` | 家具所属房间 id | 家具归属校验、交互点检索 |
| `solid` | 家具是否挡路 | 参与栅格化碰撞 |

## 4. 栅格化优先级（重要）

`map_loader.rasterize()` 与前端 `layerAt()` 使用**同一套覆盖顺序**，后者覆盖前者：

```
1. 全图填 BLOCKED
2. ground    → 可通行（道路/广场/草地/停车场/步道/车棚）
3. buildings → 建筑实体，不可通行
4. rooms     → 室内可通行（在建筑轮廓里"挖"出来）
5. furniture → 仅 solid=true 的家具不可通行（贴墙的书架、吧台、前台、会议桌等）
```

由此得到两个很省事的性质：

- **建筑轮廓内、房间之外的空隙，自动成为墙体**。画平面图不用手工摆每一道墙，房间之间留 2m 缝就是墙。
- **房间与走廊只要矩形相接就是连通的**。大厅不直接接走廊时，加一个门厅把两者接上即可（`sem_1f` 的南门就是这么做的：24m 宽的大厅用 8m 宽的门厅收成出入口）。

**门是自动推导的**，不需要写进数据：`computeDoors()` 找出每个房间与走廊相接的公共边，取中间 2m 作门。这既是渲染用的门槛，也是后面给智能体用的出入口数据（前端可通过 `state.doors` 取到）。

## 5. 编辑地图

1. 直接改 `world/maps/*.json`。
2. 跑校验：
   ```bash
   python -m world.map_loader --map world/maps/sem_1f.json --check
   ```
3. 看字符版确认大形状：
   ```bash
   python -m world.map_loader --map world/maps/sem_1f.json --ascii
   ```
   图例：`=` 道路　`+` 广场　`,` 草地　`P` 停车场　`b` 车棚　`-` 步道　`X` 建筑实体　`#` 房间　`:` 走廊　`o` 实体家具　（空格）不可通行
4. 刷新浏览器（服务端已禁缓存，F5 即可）。

### 校验器会检查

| 级别 | 检查项 |
| --- | --- |
| ERROR | id 重复 · 要素越界 · 尺寸非正 · 建筑互相重叠 · 同层房间重叠 · 房间超出所属建筑 · 家具超出所属房间 · 家具的 room 不存在 · 出生点落在不可通行格 |
| WARN | 房间与走廊不连通（并查集判定）· 房间从入口出发不可达（栅格洪水填充）· 实体家具互相重叠 · 楼层未在 floors 中登记 · 家具未声明 room |

### 加一间房的检查清单

- [ ] `rooms` 里加条目，`rect` 完全落在所属建筑轮廓内
- [ ] 房间之间留 ≥ 1m 缝（推荐 2m），否则会被判为重叠
- [ ] 保证它与某条走廊**贴边**，或通过其它房间间接连通
- [ ] 家具的 `room` 指向它，且家具矩形完全落在房间里
- [ ] 跑 `--check`，确认 0 错误 0 警告

## 6. 已知取舍

- **房间级布局与家具布置是推定**，不是测绘成果。已确证的只有：大楼位于凌水校部与西部校区之间、中国大连高级经理学院东侧、北侧紧邻大工路；总建筑面积 36000 m²，地上 3–6 层，2016 年竣工；功能含行政办公 / 专业学位培训教室 / 科研实验用房 / 多功能厅 / 教师办公室 / 研究生用房。
- 两篇官方报道对相邻道路方位表述不一致（一篇作"北侧与东侧"、一篇作"北侧与西侧"），场景二取**大工路在北、老红凌路在西**，分歧记在 `meta.notes` 里。
- **只有 1F 建模**，2F–6F 与 B1 在 `floors` 中登记为 `pending`。要做多层需要实现垂直交通（`vertical` 类房间就是入口）。
- **课桌椅子不挡路**，只有贴墙的大件标了 `solid`。否则教室会变成迷宫，A\* 也容易找不到路。要做"坐下来"这类精细行为时再逐个调整。
- 只有矩形几何，没有多边形与曲线路径。
